# 市场周期研究基础

首次了解项目整体路径，先读 [research-guide.md](research-guide.md)；本文负责概念、
术语和长期边界。

## 1. 文档定位

本文是项目的概念权威，负责回答：我们研究什么、核心术语是什么、Brooks
Market Cycle 与 O'Neil M 各自描述什么，以及怎样判断一种状态表示是否有价值。

`canonical` 只表示本文是项目当前采用的概念基线，不表示其中的研究假说已经被
数据证明。已确认选择见 [decisions.md](decisions.md)，当前研究方案和开放问题见
[research-plan.md](research-plan.md)。

本文不负责：

- 记录讨论过程和被舍弃方案；
- 给出生产 API、类结构或数据库设计；
- 声称当前 SPX 正处于某个市场状态；
- 把状态直接转换为买卖、仓位或订单；
- 证明 Brooks 或 O'Neil 的经验规则具有超额收益。

## 2. 项目命题

项目要研究的是一种市场上下文与状态表示：把截至当前的大量市场历史，压缩成
较小但仍保留决策相关信息的结构化表示。

它主要回答：

1. 当前价格过程或市场环境怎样描述；
2. 这个判断依赖哪些事实、路径和事件；
3. 新数据会加强、削弱还是否定当前判断；
4. 哪些信息在压缩中被丢弃，丢弃后是否仍有增量价值；
5. 当前表示对后续路径或策略适用性是否有样本外信息。

它不直接回答“今天买哪只股票”或“指数明天涨多少”。状态模块和交易政策必须
分离，依据 [D-004](decisions.md#d-004-状态分析与交易决策分层)。

## 3. 共同方法论

### 3.1 动态市场观

O'Neil M 和 Brooks 价格行为都不是一次性、无条件的静态预言。它们更接近在线
状态估计：昨天的判断加上今天的新证据，形成今天的判断。

\[
M_t = U(M_{t-1}, x_t, W_t, E_t)
\]

其中 `M` 是当前记忆，`x_t` 是新增数据，`W_t` 是仍需直接读取的近期窗口，
`E_t` 是有序事件记忆。递归更新是一种计算方式，不自动等于 HMM，也不保证
内部状态已经充分保存了历史。

所谓“不预测”需要准确理解。任何交易行动都隐含对未来路径的条件判断。动态
体系反对的是单一路径、永久不改的点预测，采用的是情景和条件分布：

> 根据截至当前的证据持有一个条件判断，并预先知道什么证据会改变它。

### 3.2 测量和状态必须有坐标

市场不存在脱离坐标的唯一“真实方向”，也不存在脱离参考范围的“路径效率”或
“回调深度”。任何测量或状态至少绑定：

```text
instrument / universe
timeframe
as_of
temporal_reference
estimator_version
research_objective
```

例如 SPX 日线的再平衡、SPX 60 分钟的平衡和某只股票日线的向上扩张可以同时
成立。不同坐标的状态不能直接互相否定，也不能混入同一个横截面统计。

`temporal_reference` 说明测量相对于哪段历史成立。当前区分三类时间参考系：

```text
固定窗口：最近 n 根 K 线
规则事件：从某个突破、逃逸或 Day 1 起
结构假说：假设某个几何锚点是当前路径或腿的起源
```

固定窗口不是无假设的真相，只是起止边界由日历机械给定；结构假说也不是更高层的
真相，而是需要接受因果性、稳定性和信息增量检验的候选解释。

### 3.3 统一术语

| 概念 | 含义 | 例子 |
|---|---|---|
| Observation | 原始或直接观察事实 | 当日上涨、K 线区间、成交量 |
| Temporal Reference | 一项测量采用的时间范围与锚点语义 | 最近 20 日、突破后路径、候选上涨腿 |
| Feature | 对行为强弱的连续测量 | 路径效率、重叠度、回调深度 |
| Event | 具有时序意义的离散变化 | 突破候选、追盘日、失败突破 |
| State | 会持续一段时间的行为体制 | 平衡、方向性持续、确认上涨 |
| Transition | 状态之间的转换过程 | 向外扩张、再平衡 |
| Episode | 当前状态怎样形成的完整路径 | 从区间突破后运行并出现三次回调 |
| Estimate | 某个模型对当前状态的判断 | Brooks-inspired 日线状态 |
| Context | 多个状态、事件、属性和分歧的集合 | 全局上涨但局部再平衡 |
| Policy | 下游如何解释上下文 | 提高门槛、降低某策略风险预算 |

Feature、State 和 Policy 不能压成一条规则。Feature 也不是同一种对象：固定窗口
效率只依赖预设尺度，突破保留率依赖事件锚点，当前腿效率则条件于一个结构假说。
后两者必须显式绑定参考系，不能省略起点后伪装成普通日度特征。连续特征是状态
证据；状态是否改变由事先定义的转换逻辑决定；是否交易还需 Alpha、风险、成本和
组合约束。

### 3.4 描述、条件预测与决策分离

技术分析叙述经常混合三个层次：

1. 描述：当前是趋势、区间或确认上涨；
2. 条件预测：该状态下延续、回撤或失败的分布怎样；
3. 决策：结合持仓、成本和风险后是否行动。

一个描述可以复现但没有预测价值；一个预测可以有统计价值但交易后无利润；一个
低胜率判断也可能因收益风险比形成好决策。项目必须分别验证这三层，不能用交易
盈亏反向定义当时的状态。

### 3.5 四种不确定性

| 类型 | 正确表达 | 不能接受的替代 |
|---|---|---|
| 随机性不确定 | 条件结果分布 | 事后只解释已发生路径 |
| 状态不确定 | 多个候选或 `UNRESOLVED` | 强制唯一标签 |
| 结构边界不确定 | candidate / confirmed / invalidated | 用未来确认回填起点 |
| 定义不确定 | 补足操作定义或承认未形式化 | 用“市场复杂”掩盖定义缺口 |

严谨系统可以不确定，但不能含糊到无法复现和证伪。

### 3.6 过滤、平滑与重绘

实时判断只能使用 `t` 时刻以前的信息：

\[
P(Z_t \mid O_{1:t})
\]

事后复盘很容易无意中使用未来信息：

\[
P(Z_t \mid O_{1:T}), \quad T > t
\]

后者更清楚，但不能冒充前者。一个合格的事件或路径候选至少区分：

```text
anchor_at
candidate_at
confirmed_at
effective_at
invalidated_at
as_of
```

`anchor_at` 是可选的几何追溯点；`candidate_at` 是算法首次提出候选、因而当时真正
可知的时点。两者可以不同。`effective_at` 由协议规定候选从何时允许被下游使用，
`as_of` 是本次输出的时点。

未来可以使候选失败，也可以改变当前观点，但不能删除“当时确实出现过候选”这一
历史事实。相同数据和版本下，逐根增量计算与逐日截至当日批量计算应一致。

### 3.7 记忆与压缩

实际系统不应要求一个固定向量记住一切，也不应每次只看完整原始历史。合理记忆
分层包括：

1. 不可变原始数据；
2. 近期原始工作窗口；
3. 固定窗口、规则事件和结构假说等时间参考系；
4. 条件于各参考系的测量；
5. 有序事件账本；
6. 若某个模型采用 Episode，则保存其候选起源、年龄和关键锚点；
7. 各固定时间周期的独立状态；
8. 多个候选解释；
9. 必要时按需检索的相关历史。

状态表示的中心矛盾是：压缩过强会把未来含义不同的历史混成同一状态；保留过多
则会造成维度爆炸、样本稀疏和叙事过拟合。

因此，内部表示应按信息类型选择容器：

| 信息类型 | 首选表达 |
|---|---|
| 强弱程度 | 连续变量 |
| 正式阶段 | 状态或体制标签 |
| 路径顺序 | 事件账本 |
| 形态关系 | 图结构 |
| 多尺度嵌套 | 树结构 |
| 多解性 | 候选集合或分布 |
| 尚未编码的局部信息 | 原始窗口 |

### 3.8 State、Health、Confidence 与 Data Quality

这四个概念回答不同问题：

- `state`：当前属于哪个预定义阶段；
- `health`：该阶段内部正负证据的强弱；
- `confidence`：标签是否清楚、证据是否一致；
- `data_quality`：输入是否足以支持判断。

未经标签、似然模型或独立校准，`health` 和所谓 `confidence` 只能称证据分数或
状态匹配度，不能解释成上涨概率或标签正确概率。

### 3.9 合格状态表示的验证

状态系统不能以“图上看起来合理”验收。至少需要：

1. 因果性：任何输出只使用当时可得数据；
2. 可复现性：相同数据、配置和版本得到相同结果；
3. 描述一致性：冻结图表上的人工或程序判断具有稳定性；
4. 状态稳定性：不会因轻微噪声或小幅参数变化完全翻转；
5. 行为可分离性：不同状态对应不同的后续路径或风险分布；
6. 增量价值：复杂表示优于简单趋势、波动和效率基线；
7. 样本外稳定性：结论不是只存在于用于定义规则的历史；
8. 消融价值：新增结构确实增加信息，而非只增加解释自由度；
9. 历史残差：已知压缩表示后，被丢弃历史不应持续提供大量增量信息；
10. 决策价值：预测改善最终是否足以改变行动，而非只有统计差异。

前向条件行为不是状态本体的唯一合法性标准，但它具有否决权：若复杂状态相对
简单基线既无条件行为差异，也无压缩、稳定或接口价值，就不应继续增加复杂度。

## 4. Brooks Market Cycle

### 4.1 研究对象

Brooks 的完整体系还包括 setup、入场、止损、加仓和持仓管理。本项目当前只抽取
Market Cycle 和价格过程识别，不尝试量化整套价格行为学。

Brooks Market Cycle 的核心命题是：价格在趋势和交易区间之间演化。典型路径为：

```text
平衡 / 交易区间
→ 突破或失衡尝试
→ 方向性快速扩张
→ 通道和方向性持续
→ 回调加深、双向交易增加
→ 再平衡和新的交易区间
```

这是一条常见路径，不是只能单向运行的自然定律。现实还包括：

```text
平衡 → 假突破 → 原平衡
方向性持续 → 再次加速 → 新扩张
宽通道 → 强反向突破 → 反方向扩张
再平衡 → 原方向恢复 → 方向性持续
```

### 4.2 项目当前的四阶段抽象

原始 Brooks 语言没有给出一套可直接运行的四状态程序。以下是项目从其思想中
提炼的工作抽象，不是 Brooks 官方状态本体：

| 阶段 | 核心含义 | 性质 |
|---|---|---|
| `BALANCE` | 价格围绕某一区域双向交易，方向效率低 | 较稳定体制 |
| `EXPANSION` | 价格正在离开原平衡区域，波动和失衡上升 | 转换过程 |
| `DIRECTIONAL` | 方向性得到持续，回调相对可控 | 较稳定体制 |
| `REBALANCING` | 原方向尚存但效率下降，双向性和新接受上升 | 转换过程 |

把四者做成互斥状态只是候选方案。`BALANCE/DIRECTIONAL` 作为持续体制、
`EXPANSION/REBALANCING` 作为转换模式，可能更符合其语义；这一点属于
[H-002](research-plan.md#h-002-持续体制与转换过程应分开)，尚待验证。

### 4.3 基础行为维度

研究不应一开始就识别三推、双底、楔形或高二，但也不能把依赖路径边界的维度
伪装成固定窗口特征。以下行为既可以在固定窗口内测量，部分也可以条件于规则事件
或候选路径测量；两种版本回答的问题不同：

| 维度 | 要回答的问题 | 典型证据 |
|---|---|---|
| 方向偏置 `D` | 净推进是否稳定偏向一侧 | 稳健斜率、摆动不对称、中心迁移 |
| 路径效率 `E` | 走过的路程有多少转成净位移 | 净位移 / 累计绝对变动 |
| 双向性 `B` | 多空双方是否都能取得阶段进展 | 重叠、方向熵、均值穿越、摆动对称 |
| 扩张 `X` | 是否真正离开此前活动区域 | TR/ATR 异常、边界逃逸、保留 |
| 回调结构 `P` | 反方向运动有多深、多久、多有效 | 深度、持续、反向效率、结构破坏 |
| 成熟与衰竭 `M` | 单位波动消耗能否继续产生新进展 | 边际推进下降、回调加深、失败延伸 |

这些维度不能简单相互替代。方向偏置高但双向性也高，可以描述宽多头通道；趋势
强度高而成熟度也高，可以描述“仍强但高潮化”。

归档对话曾为这些维度提出具体公式、复合项和状态匹配函数。它们具有研究参考价值，
但成熟度不同，统一保存在 [Brooks 测量候选目录](brooks-measurement-candidates.md)：
目录保留原式，同时标明数据依赖、可用时点、前视风险、缺失定义和建议阶段。公式
进入目录不表示项目已经采用；正式公式必须经过研究协议选择、版本化和验证。

### 4.4 三类结构表达

Brooks-inspired 表示长期大概率需要三类互补结构：

1. **价格占用代理**：价格反复停留、穿越和收盘的区域，以及中心是否迁移；
2. **路径与摆动结构**：推进腿、回调腿、主要高低点和多尺度嵌套；
3. **事件语法**：突破、跟进、失败、深回调、通道弱化和再平衡。

仅有日线 OHLC、没有成交量或盘中路径时，第一类只能称“价格占用代理”，不能
声称识别了真实成交接受或参与者公平价值。

依据 [D-011](decisions.md#d-011-phase-1a-比较固定窗口与因果路径表示)，固定窗口
表示与最小因果路径表示从第一次价格过程实验起就互为对照。这样做不是预先承诺
路径骨架正确，而是避免用固定窗口替代尚未定义的“当前腿”。若最小路径表示不能
稳定增加信息，可以接受不建立 Episode 核心层的负结论。

更复杂的紧密/普通/宽通道、多次推进、三推和多尺度嵌套仍属于后续结构实验。因果
ZigZag、Directional Change、分段线性拟合和多尺度持久性结构都是候选；单一工具
不是默认答案。结构价值不能只用前向预测增量裁决，还应检查 Brooks 语义覆盖、
Episode 和腿的复现、历史信息保留、参数稳定、检测延迟、重绘与复杂度。

### 4.5 事件与状态更新

优先研究的事件语法包括：

```text
BALANCE_ESTABLISHED
ESCAPE_CANDIDATE
FOLLOW_THROUGH
FAILED_ESCAPE
PULLBACK_DEEPENED
REBALANCING_CANDIDATE
RANGE_REESTABLISHED
OPPOSITE_EXPANSION
```

每根 K 线首先改变连续证据和候选解释，不应立即重命名全部历史。状态转换需要：

- 候选、确认和失效分开；
- 进入与退出使用滞回，减少边界抖动；
- 强反向“惊奇事件”能够覆盖普通状态惯性；
- 若该状态模型采用 Episode，则保存起源、年龄、关键边界、推进和回调记录；
- 同一事件在不同旧状态和路径中可以具有不同意义。

在同一已冻结模型版本内，状态解释不得反向移动锚点、删除失败候选或选择一个最能
证明自身的 Episode。状态与结构的联合递归可以作为后续独立模型研究，但必须与
状态盲的路径候选比较，并明确分开候选生成、状态评价和结果验证所用的证据。

### 4.6 输出边界

一个 Brooks-inspired 估计至少绑定品种、周期、时点和版本，输出可以包括：

```text
持续体制或阶段标签
方向属性
连续行为维度
候选转换
关键边界
支持与冲突证据
事件历史
数据质量
```

第一阶段不输出：

- 未校准的状态概率；
- 具体买卖或仓位；
- 利用未来确认回填的“完美”历史状态；
- 可自由切换时间周期后得出的唯一市场方向；
- 把个别教科书图形当作整体有效性证据。

## 5. O'Neil Market Direction

### 5.1 研究对象与定位

O'Neil M 描述的是整体股票市场在日线到数周尺度上是否已经建立、维持或破坏了
适合主动成长股多头风险的环境。它不是个股 Alpha，也不是完整风险模型。

可以把它理解为“市场信任或多头资格的生命周期”：

```text
市场调整
→ 反弹尝试
→ 需求确认（Follow-Through Day）
→ 确认上涨及扩散
→ 供给累积、上涨承压
→ 结构失效、重新调整
```

反弹尝试可以失败并回到调整；上涨承压也可以修复并回到确认上涨。

### 5.2 不对称结构

O'Neil M 的核心不是一个对称多空指标：

- 底部通常需要一项具有时序背景的需求确认事件；
- 顶部通常由派发、滞涨、领涨股恶化和宽度收缩逐渐侵蚀。

因此，需求更像脉冲事件，供给更像带年龄、严重度和失效条件的累积事件过程。

### 5.3 官方状态、过渡过程与关键事件

现代 IBD 公开体系的三个主要正式状态是：

```text
CORRECTION
CONFIRMED_UPTREND
UPTREND_UNDER_PRESSURE
```

`RALLY_ATTEMPT` 是从调整走向确认上涨的过渡过程，不是与上述三者完全平级的
IBD 正式状态。项目未来可以为了递归跟踪而把它工程化为显式内部阶段，但这属于
待设计的机器表示，不能写成 O'Neil/IBD 原始四状态本体。

关键事件包括：

```text
RALLY_DAY_1
RALLY_LOW_BREACH
FOLLOW_THROUGH_DAY
DISTRIBUTION_DAY
STALLING_DAY
FTD_LOW_BREACH
STRUCTURAL_BREAK / REPAIR
```

公开规则下，一个形式 FTD 至少要求：此前处于调整并已开始有效反弹尝试；反弹低点
未失守；通常发生在反弹第 4 个交易日或以后；当日涨幅达到所选规则版本的门槛；
成交量高于前一交易日。满足形式条件不代表后续上涨必然成功。

公开资料中的 FTD 涨幅门槛存在多个版本，如约 1.25%、1.5%、1.7% 至 2%。
项目实现前必须固定规则版本，不能事后选择最容易解释历史的口径。公开规则也不足
以精确复刻 IBD 内部 Market Pulse 的每次判断。

### 5.4 证据通道

O'Neil M 的大量观察可以压缩为：

| 通道 | 核心问题 | 典型内容 |
|---|---|---|
| 价格结构 | 原有趋势和关键锚点是否完整 | 高低点、均线、回撤、支撑破坏 |
| 需求确认 | 新需求是否足以改变调整状态 | Day 1、FTD、后续跟进 |
| 供给压力 | 抛售是否正在累积 | 派发、滞涨、放量破位 |
| 市场参与 | 指数变化是否得到广泛支持 | 宽度、等权差异、新高新低 |
| 领导力 | 最强股票和行业是否健康 | 突破、存活率、行业扩散 |

正式状态由路径和关键事件决定；连续通道描述状态内部质量。宽度和领导力主要是
验证器，不应与 FTD 规则混成一个无法解释的总分。

### 5.5 适合的机器表达

O'Neil M 更适合：

```text
事件驱动的状态机
+ 带严重度、年龄和失效条件的供需事件账本
+ 横截面参与和领导力验证
+ 多指数独立状态与分歧
```

当前 SPX 数据层没有可靠指数成交量、市场宽度、领导股或多指数数据，因此现阶段
不能实现严格 FTD、派发和完整 O'Neil M。这是延后该模块的实际数据边界，不是
对其理论价值的否定。

### 5.6 证据边界

O'Neil/IBD 关于 FTD、派发和历史牛市的许多统计来自机构内部经验研究，缺少完整
公开数据库、规则版本和独立样本外复现。它们适合作为待检验的风险协议，不应写成
市场定律或未经验证的概率。

## 6. Brooks 与 O'Neil 的关系

| 维度 | Brooks Market Cycle | O'Neil M |
|---|---|---|
| 核心问题 | 价格处于平衡、失衡、持续还是再平衡 | 整体市场是否建立并维持多头信用 |
| 对象 | 任意固定品种和 K 线周期 | 整体股票市场 |
| 粒度 | 局部、细、连续 | 全局、粗、事件驱动 |
| 关键记忆 | 边界、起源、推进、回调和通道变化 | 反弹低点、FTD、派发和扩散 |
| 对称性 | 多空过程大体对称 | 底部与顶部明显不对称 |
| 当前角色 | 首要研究对象 | 后续宏观环境模块 |

两者不能合并为同一套标签或简单加权平均。长期可检验的融合路线是：

```text
每个证券独立的 Brooks-inspired 状态
→ 全市场、行业和领导群体的状态分布
→ 状态之间的迁移流、成熟度、同步性和集中度
→ 作为 O'Neil 宏观状态的内部质量验证
```

传统宽度回答“有多少股票现在较强”；过程感知的横截面进一步回答“有多少股票
正在启动、持续、衰减或反向，它们从哪些群体向哪些群体传播”。

必须避免循环论证：O'Neil 状态可以改变个股 Brooks 状态的解释背景，但不能修改
个股的原始分类；个股状态必须独立估计后再聚合。

## 7. 远期系统边界

长期系统可以有以下逻辑层，但它们不是当前必须一次建成的软件架构：

```text
时点一致的数据与质量
→ 公共观察和无锚点测量
→ 时间参考系与结构假说
→ 条件于参考系的测量、事件与记忆
→ 专业状态估计器
→ 共识、分歧和层级关系
→ 不可变 Market Context 快照
→ 策略特定的政策适配
→ Alpha、风险、组合和执行
```

专业估计器之间应独立计算、联合解释。统计模型若未来加入，适合作为影子模型或
变化预警，不能用规则状态作输入后再反过来伪装成独立验证。

## 8. 项目红线

1. 不把原始 AI 对话中的建议自动视为项目决策。
2. 不把四个 Brooks 阶段写成已经存在的客观市场本体。
3. 不把无成交量的日线价格占用代理解释成真实市场接受。
4. 不用未来信息生成或回填历史状态。
5. 不用总分直接替代路径、事件和状态转换。
6. 不把证据分数称为概率，除非经过独立校准。
7. 不因单个指数上的清晰结果推断个股或盘中可迁移性。
8. 不以少数典型图表、流畅解释或一次状态转换作为有效性证明。
9. 不因复杂表示失败就不断增加形态、例外和模型自由度。
10. 不让状态估计器直接生成订单。
11. 不把固定窗口测量解释成当前趋势腿测量，也不省略情节条件测量所依赖的参考系。
12. 不让状态结果在同一版本内反向选择最能支持该状态的路径起点。
