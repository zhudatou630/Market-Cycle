# 项目决策记录

本文只记录已经确认的选择及其理由。工作假说和开放问题属于
[research-plan.md](research-plan.md)，历史讨论属于 `docs/references/`。

状态定义：

- `CONFIRMED`：当前生效；
- `SUPERSEDED`：已被后续决策替代；
- `REJECTED`：明确否决，不应反复提出而不提供新证据。

决策记录只追加、不覆写历史。新决策替代旧决策时，新记录必须填写
`Supersedes: D-xxx`，旧记录改为 `SUPERSEDED` 并填写
`Superseded by: D-xxx`。

## D-001 SPX 日线是 v1 唯一主价格序列

- **日期**：2026-07-22
- **状态**：`CONFIRMED`
- **决定**：v1 只实现 Yahoo `^GSPC`（别名 `SPX/GSPC`）现金指数日线 OHLC。
  周线由日线重采样，不单独下载；不把 SPY 当主序列；不保存指数 volume。
- **理由**：研究对象对准市场点位而非可交易代理；先闭环一个低复杂度价格层；现金
  指数没有可直接解释为全市场交易活动的可靠“自身成交量”。
- **替代项**：SPY、OpenBB、多指数、价格加量能和宽度。
- **影响**：当前可以研究价格过程，不能据此实现严格 O'Neil FTD、派发和市场内部
  结构；成交量和宽度需要后续独立数据源。
- **实现**：`src/market_cycle/data/bars.py`
- **来源**：`.pi/grill/2026-07-22-0314——SPX数据层.md`

## D-002 SPX 数据采用单一 parquet 权威缓存

- **日期**：2026-07-22
- **状态**：`CONFIRMED`
- **决定**：数据保存在 `data/raw/spx_daily.parquet`，字段为
  `date/open/high/low/close`。无缓存且 `refresh=False` 时自动下载并警告；
  `refresh=True` 时全量覆盖，失败硬报错，不回退旧缓存。Yahoo 使用
  `auto_adjust=False`，日期为无时区交易日。
- **理由**：研究阶段数据量小，单文件和全量覆盖比生产增量管道简单；显式刷新不能
  假装成功。
- **替代项**：CSV、双写、增量追加、刷新失败后使用 stale cache。
- **影响**：正式实验必须另行记录数据哈希和抓取元数据，否则覆盖刷新会破坏结果
  可追溯性；生产增量更新明确延后。
- **来源**：`.pi/grill/2026-07-22-0314——SPX数据层.md`

## D-003 先在 SPX 日线上研究 Brooks Market Cycle

- **日期**：2026-07-22
- **状态**：`CONFIRMED`
- **决定**：第一个具体研究对象从 Brooks Market Cycle 开始，先使用已经具备数据
  的 SPX 日线建立和检验基础价格过程表示，再考虑其他指数、个股横截面和 O'Neil
  融合。
- **理由**：Brooks Market Cycle 主要依赖价格路径，适配当前 OHLC 数据；指数减少
  公司事件和流动性差异，适合先隔离基本定义问题；一开始处理大量个股会混入过多
  无关复杂性。
- **边界**：这不表示 Phase 1 永远只允许 SPX，也不表示指数状态更“正确”；后续可
  加入少量异质指数做冻结规则验证。四个阶段、具体特征、样本起点和验证标准仍未
  确认。
- **来源**：历史对话 19；用户在 2026-07-22 当前对话中明确“打算用美股的 SPX
  来做研究，主要想从 Brooks 的模块做起”。

## D-004 状态分析与交易决策分层

- **日期**：2026-07-22
- **状态**：`CONFIRMED`
- **决定**：当前模块负责描述市场状态、路径、证据和不确定性，不直接生成买卖、
  仓位或订单。
- **理由**：状态描述、条件预测和交易决策是不同问题。交易还需要 Alpha、风险、
  组合、成本和执行；把它们混在一起会使状态定义被盈亏反向污染。
- **影响**：研究验证优先看因果性、稳定性、条件行为和增量信息，不以收益最大化
  调整状态定义。
- **来源**：历史对话 03、07-13；用户多次明确“量化分析模块，而非量化交易”。

## D-006 Brooks 结构表示分阶段引入

- **日期**：2026-07-22
- **状态**：`SUPERSEDED`
- **Superseded by**：`D-011`
- **决定**：第一阶段不把 ZigZag、摆动树或其他显式路径骨架作为基础测量的前置
  条件；完成基础行为和事件基线后，在 SPX 上设置独立的路径与形态结构阶段。要
  较完整地表达 Brooks 的通道、腿、多次推进和成熟过程，大概率需要结构层，但
  当前不预选具体工具。
- **理由**：从简单行为测量起步有利于诊断和建立基线；长期完全排除结构表达又会
  丢失 Brooks 理论中关键的路径、几何和层级信息。
- **影响**：Phase 1 的“无骨架”只是阶段范围，不是假定基础变量已经是最终充分
  表示。Phase 2 同时比较无骨架、因果 ZigZag、Directional Change、分段表示和
  多尺度结构，并评价语义覆盖、信息保留、稳定性、重绘、条件行为与复杂度。
- **来源**：归档对话 15-16；用户在 2026-07-22 当前对话中确认“路径和形态结构
  大概率需要，但起步阶段不需要”。

## D-008 正式研究钉住不可变数据快照

- **日期**：2026-07-23
- **状态**：`CONFIRMED`
- **决定**：`data/raw/spx_daily.parquet` 仍是可按 D-002 刷新的工作缓存；正式研究
  使用 `data/snapshots/` 下的不可变副本。每个快照包含同名 `.parquet` 与
  `.json` 元数据，并以 `snapshot_id`（含截止日与 sha256 前 8 位）标识。当前
  Phase 0 快照为 `spx_daily_2026-07-21_d828fbc8`。新抓取必须生成新 id，不得
  覆盖已发布快照。
- **理由**：D-002 允许全量覆盖 raw；若不另钉快照，刷新会静默破坏实验可追溯性。
  工作缓存与研究锚点分离，比禁止 refresh 或把 raw 当作不可变文件更清晰。
- **替代项**：只在报告中记录哈希；把 raw 直接当不可变；禁止日常 refresh。
- **影响**：任何测量、事件、验证结果必须引用 `snapshot_id`；不能只写“用了本地
  SPX 缓存”。质量事实与样本规则见
  [phase0-data-quality.md](reports/phase0-data-quality.md)。
- **来源**：Phase 0 收口；用户确认方案 B。

## D-010 Phase 1A 尺子与齐套研究起点

- **日期**：2026-07-23
- **状态**：`CONFIRMED`
- **Supersedes**：`D-009`（研究样本起点与对外样本定义）
- **决定**：
  1. Phase 1A 共享尺子只提供相对尺度：`tr_pct`、`atr_pct_14`（及日期）。绝对
     TR/ATR 仅实现中间量，不进研究表。
  2. `TR` 为经典 True Range；`atr_pct_14 = WilderATR(TR,14) / Close_t`；
     `tr_pct = TR / Close_t`；分母均为**当天**收盘价。
  3. ATR 预热为连续 **28** 根完整 TR（2×14）。研究表从齐套首日起裁切，不保留
     尺子空缺头。当前快照上 `research_start = 1984-02-10`。
  4. 对外样本仍名 `spx_ohlc_main_1984`，**研究行集合为 `date >= 1984-02-10`**
     （本快照至 2026-07-21）。尺子与 OHLC **同级落盘**为研究日表
     （`…__ruler_v1_atr14w28__research.parquet`）；测量模块读该表，禁止自算
     TR/ATR。
  5. 加载预热可使用 1984-01-03 起的 bar（OHLC 干净下限），但这些行不进入研究表。
  6. 资格原则延续：不删史实、不伪造 high/low、不跳坏点、不借用 1984 前补窗。
- **理由**：跨年研究需要相对波动尺；统一入口避免口径漂移；齐套裁切避免下游反复
  处理 NaN 头。详见 `.pi/grill/2026-07-23-0350——Phase1A尺子.md`。
- **替代项**：对外双日期 id；第 14 根即用 ATR；研究表保留绝对 ATR；模块内各自算 TR。
- **影响**：滚动特征的 lookback 仍须落在研究表内或由该特征协议显式声明；不得为
  补窗重新引入 1984-02-10 之前的研究行。实现：`src/market_cycle/data/ruler.py`。
- **来源**：Phase 1A 尺子 grill；用户确认相对尺、Wilder14、28 日预热、单一对外起点。

## D-011 Phase 1A 比较固定窗口与因果路径表示

- **日期**：2026-07-24
- **状态**：`SUPERSEDED`
- **Superseded by**：`D-013`
- **Supersedes**：`D-006`
- **决定**：不再预设“先完成无结构基础测量，Phase 2 再研究路径结构”。Phase 1A
  直接比较两种价格过程表示：固定窗口、多尺度连续表示；以及一种最小、因果、
  明确记录锚点与识别时间的路径表示。两者使用同一 SPX 日线快照和共享尺子，互为
  对照。状态压缩在表示比较之后；复杂形态、多尺度摆动树和多算法融合仍不进入
  当前最小实验。
- **概念边界**：时间参考系是所有测量必须显式声明的坐标。固定窗口、规则事件和
  路径分段是不同类型的参考系；任何具体 ZigZag、Directional Change 或变化点算法
  都只是待验证候选，不是底层市场本体。当前只统一 `as_of`、锚点语义、候选、确认、
  失效和版本等因果契约，不建设通用 Episode 平台。
- **理由**：D-006 把显式路径结构后置，却允许 Phase 1 使用“当前腿”“顺势回调”
  和“平衡 Episode 后首次逃逸”等依赖结构的对象，造成隐式分段和循环定义。项目
  尚处早期且没有特征或状态实现，应先让固定窗口与因果路径表示正面比较，再由证据
  决定路径结构是否成为 Brooks 模块的核心能力。
- **影响**：Phase 1A 改为价格过程表示比较；`BM-E-01` 固定窗口族保留为基线，
  同时从路径候选中预注册一个最小因果方案及有限稳健性变体。比较重点包括因果
  重放、参数稳定、检测延迟、路径信息保留、Brooks 语义覆盖和复杂度。Phase 1B
  只有在表示比较完成后才讨论状态压缩；Phase 2 只承接更复杂的路径与形态结构，
  不再负责第一次检验显式路径是否有价值。
- **来源**：归档对话 20-21 的起点识别与架构讨论；用户在 2026-07-24 当前对话中
  确认先按“固定窗口表示与最小因果路径表示正面对比”的路线修正文档。

## D-012 Phase 1A 最小因果路径 v1

- **日期**：2026-07-24
- **状态**：`SUPERSEDED`
- **Superseded by**：`D-013`
- **决定**：Phase 1A 轨道 B 采用 `bm_g_01_atr_reversal_v1`。它用 `high/low`
  更新候选极值，只在收盘 `close` 跨越锚点日冻结的 ATR 阈值时确认反转；阈值为
  $\theta_a=k\cdot C_a\cdot\mathrm{atr\_pct\_14}_a$，主版本 $k=2$，有限
  稳健性版本 $k\in\{1,3\}$。轨道 B 与轨道 A 共享 OHLC 最短可见路径 $L_i^{\min}$
  口径，正式共同样本从 1984-05-14 开始。
- **因果契约**：候选高低点替换时记录失效，收盘跨阈值时
  `confirmed_at = effective_at = as_of`；确认日的新方向候选从 `close` 起步，下一日
  才恢复用 `high/low` 更新。研究首日以单一收盘 seed 内部预热，首次正常反转确认才
  成为 `path_ready_at`；预热不作为市场状态输出。每日快照与候选账本分开，开发期按
  需计算，只有选定版本才版本化落盘。
- **理由**：这提供了一个最小、逐日因果、可审计的路径参考系，与固定窗口表示进行
  正面对比，同时避免把事后转折、日线未知内部顺序或通用 Episode 平台偷带入研究。
- **影响**：关闭 [Q-008](research-plan.md#q-008-phase-1a-采用哪种最小因果路径表示)。
  复杂形态、多尺度路径和通用 Episode 平台仍延至 Phase 2；选择块仍可拒绝当前
  路径定义，不能把本决策解释为路径结构已经有效。
- **实现与协议**：`src/market_cycle/measurements/path.py`；
  [phase1a-working-protocol.md](phase1a-working-protocol.md)。
- **来源**：`.pi/grill/2026-07-23-1613——路径效率边界.md`；用户在 2026-07-24
  当前对话中逐项确认路径参考系、阈值、初始化和时间契约。

## D-013 基础连续行为层优先，路径结构按需后置

- **日期**：2026-07-25
- **状态**：`CONFIRMED`
- **Supersedes**：`D-011`（Phase 1A 将固定窗口与最小路径作为同层基础表示的架构
  优先级）、`D-012`（`bm_g_01_atr_reversal_v1` 在 Phase 1A 的基础轨道角色）
- **决定**：
  1. Phase 1 的基础表示只研究固定窗口、多尺度、无需显式腿或摆动边界的连续行为量。
     当前实现从 `BM-E-01-OHLC-min v1` 开始，后续可在同层加入方向、双向性、重叠和
     扩张；它们都必须显式声明窗口和 `as_of`，但不得依赖路径锚点。
  2. 基础层不得使用“当前腿效率”“回调深度”“路径年龄”“Episode 起源”等路径相对
     语义。若某研究问题需要这些对象，必须在 Phase 2 先建立独立、因果、可审计的
     结构解析协议。
  3. `bm_g_01_atr_reversal_v1` 及其候选账本、前缀重放测试和时间契约保留为
     `structures` 下的单尺度因果摆动参考候选；它不再是 Phase 1A 的连续状态输入、
     正式比较轨道或基础审计页内容。
  4. Phase 2 从具体结构表达需求出发，重新比较当前 ATR 路径、多尺度 Directional
     Change、分段线性或其他结构候选。当前 ATR 路径不是默认骨架，也不因已有实现而
     获得优先权。
- **理由**：严格 `as_of` 图表审计和公式复盘表明，两类对象承担不同职责。固定窗口
  效率是跨尺度的稠密连续行为量；最小 ATR 路径是候选极值、确认与锚点重置构成的
  局部结构解析器。为避免隐式、事后腿而提前引入路径，正确识别了路径相对语义的
  因果风险，却过早把路径分段提升为基础状态表示的前置条件。时间参考系必须显式，
  不等于路径分段必须基础化。
- **影响**：Phase 1A 的协议、研究计划、导航、基础审计页和包结构都以连续行为层为
  中心重写。Phase 1 不再比较“固定窗口是否足以击败最小路径”；它检验多尺度连续
  表示是否足以构成基础价格过程底图。路径结构的价值保留到 Phase 2 的明确结构问题
  中检验，且不得用当前 B 的视觉表现、已投入代码或未来收益决定其角色。
