# 市场周期项目研究操作指南

## 1. 这篇指南解决什么问题

这是项目的第一阅读入口。它说明研究从哪里开始、为什么分层、当前做到哪里，以及
不同结果会如何改变下一步。它不拥有公式、假说或决策：

- 概念和边界以 [foundation.md](foundation.md) 为准；
- 当前阶段、假说和开放问题以 [research-plan.md](research-plan.md) 为准；
- 已确认选择以 [decisions.md](decisions.md) 为准；
- 候选公式以 [brooks-measurement-candidates.md](brooks-measurement-candidates.md) 为准；
- 代码和测试说明实际行为。

## 2. 项目最终想得到什么

项目要建立可解释、可复现、时点一致的市场过程与状态表示，帮助回答：当前价格过程
更接近平衡、方向持续、扩张还是再平衡；哪些连续证据支持该判断；哪些信息会削弱它。

项目不是交易系统，不直接下单；当前只研究 SPX 日线 OHLC。Brooks 是概念来源，不是
已承诺完整复刻；O'Neil、量能、宽度和横截面均在后续独立阶段。

## 3. 当前架构原则

D-013 确认以下分层：

```text
SPX 日线 OHLC
        ↓
共同几何与尺度层
TR / ATR / OHLC-min 路径下界等
        ↓
基础连续行为层
多尺度方向、效率、双向性、重叠、扩张
        ↓
基础价格过程表示
连续表示，或可选的初级状态压缩
        ↓
明确出现结构表达需求
腿、回调、区间边界、通道、三推、双底
        ↓
路径与形态结构层
摆动候选、价格区域、关系图、多尺度嵌套
```

关键区别：**所有测量都必须显式声明时间参考系；但基础连续特征不必先经过路径分段。**

固定窗口回答“最近 $n$ 个交易日怎样”。当研究问题真正需要当前腿、回调比例或形态
关系时，才在结构层建立因果锚点和候选/确认契约。不能把算法拐点当成市场本体，也
不能在基础层偷用未定义的“腿”。

## 4. 整体研究地图

```text
Phase 0  数据快照与质量边界
    ↓
Phase 1A 基础连续行为表示
    ↓
Phase 1B 可选状态压缩
    ↓
Phase 2  路径与形态结构解析
    ↓
Phase 3  少量异质指数冻结验证
    ↓
Phase 4  高流动性个股压力测试
    ↓
Phase 5  周期分布与迁移流
    ↓
Phase 6  O'Neil M、宽度、领导力和独立成交量代理
    ↓
Phase 7  Market Context 与策略政策、风险和组合接口
```

每个阶段都可得出“足够”“不足”“不稳”或“实验无效”的结论。模块已经实现不构成
保留理由；结构工具必须证明补充了连续底图无法恢复的信息。

## 5. 共同研究循环

1. **明确问题**：说明该特征或结构要补充什么信息。
2. **选候选并补操作定义**：声明输入、窗口或锚点、标准化、可用时点、参数与版本。
3. **先验证工程因果性**：快照可追溯、前缀重放一致、候选和确认不回填。
4. **再验证研究含义**：连续时间块、稳定性、信息保留、语义覆盖和复杂度。
5. **明确处理**：采用、拆分、延后或拒绝；失败候选保留为研究资产，不自动升级。

图表用于发现公式语义与反例，不是正式通过证据；未来收益不是当前基础表示的选择
目标。

## 6. 当前 Phase 1A

当前正在建立连续行为层。已实现：

- 效率 `BM-E-01-OHLC-min v1`；
- 方向 `BM-D-01-theilsen-atr v1`；
- 双向性 `BM-B-01-entropy-overlap v1`。

三者共用 `{5,10,20,55}` 窗口与等权 / 中长期优先两种跨尺度压缩。它们描述最近
不同尺度上的直接性、中心迁移和双向再交易，不识别当前腿，也不直接产生状态标签。
当前开发任务是：

- 审计真实窗口上 `E/D/B` 的语义与互补性；
- 设计扩张等后续连续量；
- 检查尺度关系、稳定性和连续表示是否足以支持状态压缩；
- 在连续层出现明确语义缺口前，不引入结构术语或路径算法作为补救。

本地审计页只服务于这项连续表示开发。当前 ATR 反转路径不再作为该页面或 Phase 1A
的同层对照。

## 7. Phase 1A 之后的分叉

### 连续层足够

保留多尺度连续表示，进入可选的 Phase 1B，检验是否值得压缩为更简单、可解释的
状态或转换表达。

### 连续层出现明确结构缺口

记录缺少的是何种关系，例如因果腿边界、回调比例、区间测试或多次推进；在 Phase 2
为该问题建立专门结构协议。当前 ATR 路径只是结构候选之一。

### 连续定义不稳或实验无效

先修正连续公式、窗口、数据或验证协议；不以更复杂路径、形态或状态机掩盖基础问题。

## 8. Phase 2：路径与形态结构

Phase 2 研究明确的结构问题：推进腿、回调腿、区间边界、通道、三推、双底和多尺度
嵌套。每个结构候选必须记录候选、确认、失效、`effective_at` 和 `as_of`，并比较参数
稳定性、检测延迟、重绘、语义覆盖、信息保留和复杂度。

`bm_g_01_atr_reversal_v1` 保留为单尺度因果摆动参考候选及工程基线；它不是默认结构
骨架，更不是基础连续状态表示。
