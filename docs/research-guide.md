# 市场周期项目研究操作指南

## 1. 这篇指南解决什么问题

这是一篇面向研究者的第一阅读入口。它不详细定义公式，也不记录全部假说，而是
回答五个实际问题：

1. 项目最终想得到什么；
2. 当前应该从哪个子模块开始；
3. 为什么按这个顺序研究；
4. 每个阶段应产生什么，而不只是写出什么代码；
5. 结果成功或失败后，下一步分别往哪里走。

本文只负责导航，不拥有新的研究事实。发生冲突时：

- 概念和边界以 [foundation.md](foundation.md) 为准；
- 当前假说、阶段和开放问题以 [research-plan.md](research-plan.md) 为准；
- 候选公式以 [brooks-measurement-candidates.md](brooks-measurement-candidates.md)
  为准；
- 已确认选择以 [decisions.md](decisions.md) 为准；
- 实际行为以代码和测试为准。

本文也不是进度日志。项目当前做到哪里，始终查看
[research-plan.md 的“当前阶段”](research-plan.md#1-当前阶段)。

## 2. 项目最终想得到什么

项目希望建立一种市场上下文与状态表示：把截至当前的大量价格和市场信息，压缩成
较小、可解释、可复现的结构，让人或下游策略知道：

- 当前价格过程更接近平衡、扩张、方向持续还是再平衡；
- 这个判断依赖哪些测量、事件和历史路径；
- 哪些证据支持它，哪些证据与它冲突；
- 什么新信息会加强、削弱或否定当前判断；
- 这种表示是否比简单趋势和波动指标多保留了有用信息。

它不是一开始就生产买卖信号，也不是把 Brooks 和 O'Neil 规则机械翻译成一个总分。
状态描述、条件行为和交易决策是三个不同层次。

当前实际范围比远期目标小得多：只有 SPX 日线 OHLC 数据层，研究优先从 Brooks
Market Cycle 开始。完整复刻 Brooks 还是建立 Brooks-inspired 表示，仍是
[Q-001](research-plan.md#q-001-研究目标是-brooks-复刻还是-brooks-inspired-表示)。

## 3. 为什么必须分阶段

这个项目容易同时吸引很多东西：四状态、形态、ZigZag、多尺度、HMM、个股、宽度、
领导股、O'Neil 和交易策略。如果同时展开，任何结果都很难诊断：不知道是数据、
公式、状态定义、路径提取还是统计验证出了问题。

分阶段不是认为后面的结构不重要，而是建立可比较的基线：

- 没有基础测量，就不知道复杂结构究竟增加了什么；
- 没有路径事件，只测效率和趋势，容易把常识重新命名为 Brooks；
- 没有因果回放，漂亮的历史状态可能全部来自未来重绘；
- 没有前向结果和强基线，图上“合理”无法证明表示有研究价值；
- 没有先做单序列诊断，扩展到个股和横截面只会放大混乱。

所以整体顺序是：先测量，再识别事件，再压缩状态，再补充结构，最后扩展研究对象。

## 4. 整体研究地图

```text
Phase 0  数据快照与质量边界
    ↓
Phase 1A 基础行为测量 + 最小路径事件 + 条件行为验证
    ├─ 基础证据成立 ──→ Phase 1B 状态压缩比较
    └─ 基础证据不成立 ─→ 跳过 Phase 1B
                       \       /
                        ↓     ↓
Phase 2  SPX 路径与形态结构实验
    ↓
Phase 3  少量异质指数冻结验证
    ↓
Phase 4  高流动性个股压力测试
    ↓
Phase 5  全市场、行业和领导群体的周期分布与迁移流
    ↓
Phase 6  O'Neil M、宽度、领导力和独立成交量代理
    ↓
Phase 7  Market Context 与策略政策、风险和组合接口
```

这里有两个关键点：

1. Phase 1A 失败会阻止把基础变量直接包装成状态，但不会自动证明路径结构无用；
2. Phase 2 是预先规划的独立结构实验，不是 Phase 1 失败后临时增加的补丁。

任何阶段都可以得出负结论。路线图描述研究顺序，不承诺所有模块最终都值得保留。

## 5. 每个阶段都使用同一个研究循环

无论研究一个效率变量、一个突破事件还是一种摆动骨架，都按同一循环推进：

### 5.1 明确问题

先说明这个模块要补充哪类信息。例如研究路径效率，是为了测量净位移与实际路程；
研究摆动骨架，是为了表达滚动窗口无法保留的推进腿、回调腿和层级关系。

### 5.2 继承候选，而不是从头发明

Brooks 测量先从 `BM-*` 候选目录选择。保留原研究资产，同时检查该候选是否依赖
未来、volume、摆动或尚未定义的权重。

### 5.3 补足操作定义

把窗口、边界、标准化、方向、零分母、可用时点和参数全部写清楚。此时产生的是
某个版本的研究定义，不是永恒正确的公式。

### 5.4 先证明工程上可信

确认数据快照可追溯；逐日计算与截至当日批量重放一致；候选、确认和失效时间不会
被未来数据重写。

### 5.5 再检验研究含义

比较简单基线、前向路径、跨时间块稳定性和合理参数范围。典型图表用于调试，不是
正式通过证据。

### 5.6 明确做出处理

每轮研究协议应为候选记录一种处理结论：

```text
采用：进入本轮研究协议
拆分：只保留其中可解释的分量
延后：需要后续结构或数据
拒绝：当前定义不值得继续
```

这不替代候选目录中可以并存的来源、阶段、输入和时点状态。失败候选不从目录删除，
因为失败本身也是研究资产。

## 6. Phase 0：数据快照与质量边界

### 为什么先做

后续很多特征依赖 K 线区间、重叠和 TR。SPX 早期存在退化 OHLC，缓存又可能被
刷新覆盖。如果不先固定数据边界，公式是否有效与输入是否有效会混在一起。

### 主要工作

- 固定 parquet 哈希、抓取截止日和质量规则；
- 标记退化 OHLC、零区间及其影响的滚动窗口；
- 决定主研究样本和敏感性样本；
- 保留完整原始数据，不在数据层伪造或删除历史事实。

### 阶段产物

- 数据质量报告；
- 可复现的数据快照标识；
- 研究层样本资格规则。

### 进入下一阶段的条件

任意一个研究锚点都能说明自己使用了哪份数据、哪些历史窗口，以及是否满足该特征
的质量要求。

## 7. Phase 1A：基础行为测量和路径事件

这是第一个需要实现的研究子模块，但不是当前第一项工作。项目目前处于 Phase 0
收口和 Phase 1A 准备阶段，权威状态见
[research-plan 的“当前阶段”](research-plan.md#1-当前阶段)：先完成数据快照与
质量产物，再写一份允许版本化迭代的工作协议，然后开始 Phase 1A 开发。

### 7.1 基础行为测量

第一条轨道把价格行为拆成若干独立连续测量，不直接计算 Market Cycle 总分。公式
从 [候选目录](brooks-measurement-candidates.md)选择；当前允许哪些特征族、怎样
验证和何时停止，由
[research-plan 第 5 节](research-plan.md#5-phase-1a测量与路径语法探针)所有。

第一批实现的目标不是“判断当前是什么状态”，而是生成一张每日测量表，让每一列
都有清楚含义、公式版本和质量标记。

### 7.2 最小路径事件

只做连续变量容易退化成研究趋势持续性，因此第二条轨道同时研究“逃离边界、后续
跟进或失败、回调加深”等路径事件。它的核心不是事件名字，而是把当日候选与后来
确认分开，并以 Episode 为样本。具体事件集合和时点规则仍以 `research-plan` 和
候选目录为准。

### 7.3 条件行为验证

第三条轨道把测量和事件与后续路径连接，并与简单基线比较。工作协议可以在开发期
显式迭代，但每次版本都要留痕；进入锁定确认块前，必须冻结公式、主假说、结果、
基线和停止条件。具体内容由工作协议和 `research-plan` 所有，本文不另列一套。

### 阶段产物

面向人的完成信号是：有可追溯的候选选择和协议版本，有可复现的测量、事件与结果
数据，有锁定确认报告，并能对基础表示给出接受、拆分、延后或拒绝的结论。正式
产物清单只维护在 [research-plan 第 9 节](research-plan.md#9-本阶段预期产物)。

## 8. Phase 1A 之后怎样分叉

### 情况一：基础测量和路径事件具有稳定信息

进入 Phase 1B，研究怎样把连续证据压缩成更易审计和使用的状态表示。

### 情况二：连续变量有效，但路径事件没有额外信息

保留连续测量，但不能宣称 Brooks 路径语法已经得到支持。Phase 1B 可以缩小范围，
只比较连续表示与最简单的持续体制，不急于建立四阶段。

### 情况三：基础测量没有超越简单基线

不进入 Phase 1B，不把这些变量重新命名成四状态。仍按计划进入独立 Phase 2，检验
失败是否来自基础滚动表示遗漏了腿、通道和 Episode 结构。

### 情况四：因果回放或数据质量不成立

这不是研究上的负结论，而是实验无效。先返回 Phase 0 或公式实现，修正后重新运行，
不能继续解释状态结果。

## 9. Phase 1B：状态压缩

这一阶段才回答“是否需要状态标签”。比较对象包括：

```text
连续行为表示
BALANCE / DIRECTIONAL 持续体制 + 转换事件
四阶段 + UNRESOLVED
```

状态压缩的目标不是凭空增加信息，而是用可接受的信息损失换取：

- 更稳定的时间序列；
- 更清楚的阶段和转换；
- 更容易审计的解释；
- 更适合作为下游接口的表达；
- 对模糊和冲突证据的诚实处理。

若离散状态丢失大量排序和路径信息，又没有带来稳定或解释价值，就保留连续表示。
四阶段不是项目必须交付的功能。

## 10. Phase 2：路径与形态结构

Phase 2 仍在 SPX 日线上进行。它处理基础滚动测量难以完整表达的：

- Episode 起源和关键边界；
- 推进腿与回调腿；
- 紧密、普通和宽通道；
- 多次推进、三推和边际生产率；
- 回调逐步加深、通道弱化和成熟过程；
- 多尺度结构嵌套。

候选包括无骨架对照、因果 ZigZag、Directional Change、分段线性表示和多尺度
摆动结构。工具选择见 [Q-008](research-plan.md#q-008-phase-2-采用哪种路径与形态表示)。

这一阶段不能只问“预测是否提高”，还要问：

- Brooks 语义是否覆盖得更完整；
- 不同执行者或算法能否复现腿和 Episode；
- 原始路径信息是否得到更多保留；
- 参数变化后结构是否稳定；
- 候选和确认时间是否严格不重绘；
- 增加的复杂度是否值得。

按照 `research-plan`，Phase 2 结束后重新检查 Phase 1B 的状态本体，因为新结构
可能表明原状态过粗、组织方式错误，或者根本不值得离散化。

## 11. Phase 3 至 Phase 7：从局部表示走向市场上下文

### Phase 3：少量异质指数

冻结 SPX 上的定义，不在新指数上重新调到好看，检查语义和条件行为能否迁移。
失败说明外部有效性有限，不自动否定 SPX 内部结果。

### Phase 4：高流动性个股

研究公司事件、跳空、流动性和更强噪声下，个体 Market Cycle 是否仍可复现。指数
上的清晰结构不能直接外推到个股。

### Phase 5：周期分布与迁移流

对个股、行业和领导群体独立估计后，再聚合状态存量、启动、持续、衰减和反向流。
这一步才开始形成比传统均线宽度更细的市场内部结构。

### Phase 6：O'Neil M

引入独立成交量、市场宽度、领导力和多指数信息，研究调整、反弹尝试、FTD、确认
上涨和供给侵蚀。O'Neil 与 Brooks 独立估计、联合解释，不能互相修改原始分类。

### Phase 7：Market Context

将多个估计器、事件、分歧和数据质量组织成时点一致的上下文快照。只有此后才讨论
策略如何读取上下文、怎样影响风险预算；状态模块仍不直接生成订单。

## 12. 当前应该做的第一批工作

当前不要同时规划 Phase 2 至 Phase 7 的代码。第一批工作按以下顺序闭环：

1. 形成正式数据质量报告和快照标识；
2. 写工作协议初稿并预留开发、选择和锁定确认块；协议在探索期可以版本化迭代；
3. 从候选目录选择第一批 `BM-*` 分量，补足窗口、时点、方向和质量规则；
4. 在开发块实现测量、事件、结果和基线，显式记录每次定义变化；
5. 使用选择块比较候选和合理参数，确定进入确认块的单一协议版本；
6. 在查看确认块前冻结公式、参数、主假说、主结果、基线和停止条件；
7. 一次性运行锁定确认，完成因果回放、稳定性和时间依赖处理；
8. 写出 Phase 1A 的正面或负面结论，再决定是否进入 Phase 1B。

研究协议和冻结时点的详细要求见
[research-plan 第 5.6 节](research-plan.md#56-因果与验证要求)，阶段正式产物见
[research-plan 第 9 节](research-plan.md#9-本阶段预期产物)。

第一个真正的完成标志不是出现一条彩色状态曲线，而是：

> 对任意一天和任意事件，都能说明使用了什么数据、公式和历史边界，当时知道什么、
> 后来才确认什么，以及它相对简单基线是否提供了稳定信息。
